# Qwen2.5-Coder-3B 首轮微调评估

首轮 4-bit QLoRA 使用 80 条训练样本、20 条验证样本训练 3 epoch，共 30 个优化 step。最终 adapter 与 `checkpoint-30` 的 SHA-256 一致，均包含 504 个 LoRA tensor，大小为 59,934,640 字节。

## 测试结果

在本机 `dw2` MySQL 快照中，以只读事务执行 20 条测试预测和对应参考 SQL：

| 指标 | 通过数 | 比例 |
| --- | ---: | ---: |
| 只读安全 | 20/20 | 100% |
| 输出契约 | 19/20 | 95% |
| 可执行 | 19/20 | 95% |
| 结果正确 | 13/20 | 65% |

测试集只有 10 个唯一问题；按唯一问题去重后，只读安全为 100%，输出契约和可执行率均为 90%，结果正确率为 50%。20 条原始样本中的前 15 条由 5 个问题各重复 3 次，因此 65% 不能视为可靠的泛化水平。

## API 基线对比

相同输入使用 `deepseek-v4-pro`、温度 0 生成 API 基线，并在同一 `dw2` 只读事务中执行：

| 指标 | API 基线 | Qwen adapter | 差值 |
| --- | ---: | ---: | ---: |
| 只读安全 | 100% | 100% | 0pp |
| 输出契约 | 100% | 95% | -5pp |
| 可执行 | 100% | 95% | -5pp |
| 结果正确 | 65% | 65% | 0pp |

按 10 个唯一问题去重后，API 与 Qwen 的结果正确率均为 50%；API 的输出契约和可执行率为 100%，Qwen 均为 90%。Qwen 未达到“结果正确率比 API 基线至少提升 5 个百分点”，且可执行率下降，因此不满足模型接入门槛。

## 失败类型

- 3 条重复样本把“2025 年 1 月订单数和销售金额”的整体汇总错误地按订单分组，返回 40 行而不是 1 行。
- 1 条订单编号查询遗漏 `LIMIT 10`，返回 115 行而不是 10 行。
- 1 条编造不存在的 `dim_member` 表，导致 MySQL 执行失败。
- 1 条订单金额查询遗漏订单编号列，行数相同但结果结构不等价。
- 1 条日期维度查询返回了错误字段并遗漏 `LIMIT 10`。

## 结论

该 adapter 达到只读安全要求，但结果正确率不足，且测试集存在明显重复，不能满足上线门槛。本轮产物应保留为离线实验，不接入应用。下一轮应先重建按查询模板隔离且无重复的测试集，并补充整体聚合、字段投影、限制条数和真实 schema 约束的训练样本。

## V2 评估（无重复、模板隔离）

V2 使用 120 条样本，按 80/20/20 划分训练、验证和测试集；测试集 20 条问题文本全部唯一，且 48 个查询模板不跨 split 泄漏。Qwen adapter 与 API 基线使用相同输入、相同 `dw2` MySQL 快照和相同只读评估策略。

| 指标 | API 基线 | Qwen adapter V2 | 差值 |
| --- | ---: | ---: | ---: |
| 只读安全 | 100% (20/20) | 100% (20/20) | 0pp |
| 输出契约 | 100% (20/20) | 95% (19/20) | -5pp |
| 可执行 | 100% (20/20) | 95% (19/20) | -5pp |
| 结果正确 | 50% (10/20) | 70% (14/20) | +20pp |

V2 满足“结果正确率至少提升 5 个百分点”和“只读安全 100%”，但不满足“可执行率不得低于基线”，因此仍不接入应用。失败集中在聚合查询被错误分组、无效表名 `dim_member`、遗漏 `LIMIT 10` 以及字段投影不完整。V2 是当前权威离线评估结果；adapter 和 `checkpoint-30` 完整性校验通过。

## V3 评估（hard-case 增量训练）

V3 在 V2 的 100 条训练样本上增加 20 条针对聚合范围、真实 schema、字段投影和 `LIMIT` 的人工审核 hard-case 样本；验证集和 20 条测试集完全沿用 V2。训练使用 4-bit QLoRA，39 个优化 step，最终验证 loss 为 `0.0522557`，token accuracy 为 `0.98703`。最终 adapter 与 `checkpoint-39` 均为 504 个 tensor、59,934,640 字节，SHA-256 为 `2857f2d6885215c2849a19d31988e866b8da56a04eb52b842499eccab8bbb5c9`。

| 指标 | API 基线 | Qwen V2 | Qwen V3 | V3 相对 API |
| --- | ---: | ---: | ---: | ---: |
| 只读安全 | 100% | 100% | 100% (20/20) | 0pp |
| 输出契约 | 100% | 95% | 95% (19/20) | -5pp |
| 可执行 | 100% | 95% | 95% (19/20) | -5pp |
| 结果正确 | 50% | 70% | 85% (17/20) | +35pp |

V3 相对 V2 的结果正确率提升 15pp，纯模型评估的可执行率仍低于 API 基线 5pp。接入时不允许绕过该缺口，而是使用受保护模式：Qwen 负责主生成，API 负责校正，静态 guard 和二次 `EXPLAIN` 负责放行，仍失败则拒绝执行。剩余离线失败为：测试样本 `retail_0117` 生成不存在的 `dim_member` 表，`retail_0119` 遗漏订单编号列，`retail_0120` 返回错误日期字段投影并遗漏 `LIMIT 10`。

## V4 评估（schema 覆盖增量）

V4 在 V3 训练集上增加 24 条客户字段、订单字段和日期字段投影样本，学习率降为 `1.5e-4`；测试集仍保持与 V2/V3 完全一致。训练完成 48 steps，最终验证 loss 为 `0.0550431`，token accuracy 为 `0.98733`。最终 adapter 与 `checkpoint-48` 完整性校验通过，504 个 tensor、59,934,640 字节，SHA-256 为 `eb0203f5ce7c32cc276a63267a3ebb1e638ffb1fe241260e7b5d0020cc13c1af`。

| 指标 | API 基线 | Qwen V3 | Qwen V4 | V4 相对 API |
| --- | ---: | ---: | ---: | ---: |
| 只读安全 | 100% | 100% | 100% (20/20) | 0pp |
| 输出契约 | 100% | 95% | 95% (19/20) | -5pp |
| 可执行 | 100% | 95% | 95% (19/20) | -5pp |
| 结果正确 | 50% | 85% | 80% (16/20) | +30pp |

V4 未达到 V3 的正确率，因此不替代 V3。当前受保护接入使用 V3 adapter；V4 保留为离线对照实验。

## 生成后门禁审计

新增 schema-aware SQL guard，按召回到的真实表/字段集合检查生成结果的单语句、只读关键字、Markdown 代码块、表名和限定字段；它不替代 MySQL 执行和结果正确率评估。V3 与 V4 测试预测均为 19/20（95%）通过静态门禁，唯一失败是 `retail_0117` 的 `dim_member` 幻觉。报告分别保存于 `data/finetuning_v3/sql_guard_report.json` 和 `data/finetuning_v4/sql_guard_report.json`。该 guard 已接入现有 `validate_sql` 节点，在数据库 `EXPLAIN` 前阻止未知表/字段和写操作，失败后仍走已有的 API SQL 校正流程。

校正流程同时已改为有限闭环：`correct_sql` 产出后重新回到 `validate_sql`，最多校正两次；第二次仍未通过时进入 `reject_sql` 并结束，不执行未经校验的 SQL。这样避免校正模型再次生成 `dim_member` 等错误后直接进入数据库。

新增 `tests/test_sql_safety.py` 覆盖未知表拦截、Markdown 代码块拦截、合法召回 schema 放行以及“拦截时不调用数据库仓储”四条回归用例，当前 `unittest` 4/4 通过。

## 受保护接入

`app/scripts/serve_qwen.py` 提供 OpenAI 兼容的本地端点，默认加载 V3 adapter：`http://127.0.0.1:8001/v1`。应用通过 `DATA_AGENT_LLM_BASE_URL` 或配置文件使用 Qwen 主生成，`correction_llm` 保持 API 模型用于校正；未配置本地端点时仍可回退到原 API 模式。Qwen 端点已完成 `/health` 和 Chat Completions 烟测。
