# 分阶段进行 SQL 生成模型微调

问数 Agent 已通过召回上下文和提示词生成 SQL，但当前 API 模型不可假设能够获取权重或直接微调。我们决定保留当前 API 模型作为基线，使用可本地训练和部署的中文代码/指令模型进行 LoRA/QLoRA 实验；第一阶段只训练“完整召回上下文到纯 SQL”的生成任务，并通过统一模型切换端点接入现有 `generate_sql` 节点。这样可以在不改变 LangGraph 编排的情况下，用隔离 MySQL 8 快照比较结果正确率、可执行率和只读安全性，再决定是否扩大范围或上线。

## Considered Options

- 直接微调当前 API 模型：权重、数据驻留和可复现性不可控。
- 同时微调整个 Agent：训练目标和误差来源混杂，难以归因。
- 只继续优化提示词：保留成本和上下文敏感性问题，作为基线而非微调替代方案。

## Consequences

- 需要维护经过复核的 JSONL 数据集和按业务隔离的测试集。
- 需要独立的推理服务或兼容端点，以及隔离的评估数据库。
- 第一阶段不覆盖澄清问句、关键词提取或召回模型的训练。
